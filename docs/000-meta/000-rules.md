# Documentation Rules

## Rationale

Seekers Guild documentation should make project decisions easy to find, review, and reuse. Docs should explain why a pattern exists, when it should be used, and what tradeoffs matter.

## Required Structure

New pattern documents should include:

- Rationale
- Pseudocode Example
- Critical Quirks
- When to Use
- When Not to Use

## Numbering

Use sequential numbers within each category. Gaps are allowed.

Examples:

- `docs/2xx-frontend/001-nextjs-app-router.md`
- `docs/2xx-frontend/005-responsive-layout-scale.md`

## Language

Write in English. Keep the tone technical but accessible.

## Code

Use language-agnostic pseudocode in general pattern docs. Put implementation details in repo-specific frontend, backend, or operations docs.

## External Links

Prefer official documentation over third-party examples.
